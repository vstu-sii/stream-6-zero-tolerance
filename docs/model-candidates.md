# Кандидаты языковых моделей и оценка вычислительных затрат

**Проект:** «Многоагентная система изучения математических дисциплин»  
**Дисциплина:** Системы искусственного интеллекта  
**Лабораторная работа № 1**  

## 1. Критерии выбора модели

В обучающей системе важен не только правильный результат вычисления. Например, при решении системы линейных уравнений студент может допустить арифметическую ошибку, неправильно применить метод Гаусса или не понять, почему элементарные преобразования строк сохраняют множество решений. Во всех трёх случаях ответ окажется неверным, но полезные пояснения будут различаться. Поэтому модель должна уметь работать с ходом решения, задавать уточняющие вопросы и формулировать подсказки с учётом обнаруженного затруднения.

Для проекта рассматриваются пять критериев: качество математических объяснений на русском языке; способность следовать инструкциям и выдавать структурированный ответ; стоимость повторяющихся запросов; доступность развёртывания и сопровождения; возможность контролировать передачу учебных данных. Поскольку проект предполагает взаимодействие нескольких агентов, отдельно учитывается стоимость цепочки запросов: одно действие студента может вызывать несколько обращений к модели.

Предварительно сравниваются три конкретных варианта: облачная GPT-5 mini, российская облачная YandexGPT Pro 5.1 и локально развёртываемая Qwen3-8B. Включение модели в список кандидатов не означает, что её качество для математического обучения уже доказано: это должно определяться на общих тестовых заданиях.

## 2. Сравнение кандидатов

| Критерий | GPT-5 mini | YandexGPT Pro 5.1 | Qwen3-8B |
|---|---|---|---|
| Размещение | Облачный API OpenAI | Yandex AI Studio | Локально либо на собственном сервере |
| Способ оплаты | По входным и выходным токенам | По входным и выходным токенам | Без оплаты токенов при собственном запуске; оплачиваются вычислительные ресурсы |
| Сильная сторона для прототипа | Удобное API, структурированные ответы и контроль расхода | Русскоязычный сервис и возможность интеграции через API | Контроль над размещением и возможность работы без внешнего API |
| Основное ограничение | Для использования в российском вузе могут возникнуть сложности с доступом к API [7] | Зависимость от облачного сервиса, его тарифов и доступности | Требования к памяти и производительности, самостоятельное сопровождение |
| Что требуется проверить | Корректность математических подсказок; фактическую стоимость | Корректность рассуждений и токенизацию русского текста | Качество в выбранной квантовке, скорость на доступном оборудовании |

### GPT-5 mini

Для GPT-5 mini официальная документация указывает цену **0,25 доллара (около 20,14 ₽) за 1 млн входных токенов** и **2 доллара (около 161,11 ₽) за 1 млн выходных токенов** при стандартной тарификации текстовых запросов [1]. Поддерживаются программные интерфейсы для интеграции в приложение. Эта модель может служить облачным кандидатом при проверке сценариев диагностики, объяснения и контроля усвоения. При этом точность решения учебных задач нельзя выводить только из характеристик модели: ответ необходимо проверять на конкретных математических примерах. При использовании OpenAI API в российском вузе могут возникнуть сложности с доступом к сервису [7].

### YandexGPT Pro 5.1

YandexGPT Pro 5.1 рассматривается как российский облачный кандидат. В опубликованном компанией примере тарификации указано **0,40 рубля за 1000 входных токенов** и **0,40 рубля за 1000 выходных токенов** при синхронном запросе, включая НДС [2]. В документации Yandex Cloud описана возможность использовать генеративные модели через API [3]. Существенное условие сравнения — количество токенов в одном и том же русском тексте у разных моделей может различаться, поэтому реальные расходы потребуется рассчитывать по счётчикам конкретного сервиса, а не по единому приблизительному объёму текста.

### Qwen3-8B

Qwen3-8B — модель с открытыми весами, распространяемая по лицензии Apache 2.0. Разработчики описывают её запуск через локальные инструменты, в том числе Ollama, LM Studio и llama.cpp [4, 5]. По сравнению с облачными вариантами она позволяет оставить учебные запросы на собственном компьютере. Однако локальная установка не означает отсутствия затрат: для работы нужны память, вычислительное время, место для весов модели и ресурсы для обслуживания нескольких пользователей.

## 3. Оценка токенов для одного учебного сценария

Рассмотрим цикл работы со студентом, который неправильно решил задачу по линейной алгебре. Система получает условие, ответ и часть промежуточных вычислений; предполагаемый диагностический агент определяет причину ошибки; агент объяснения даёт подсказку; агент генерации предлагает аналогичное упражнение; агент оценки проверяет новый ответ.

Для предварительной оценки приняты следующие **расчётные допущения**, а не результаты фактического измерения:

| Обращение к модели | Входные токены | Выходные токены |
|---|---:|---:|
| Диагностика ошибки | 900 | 250 |
| Объяснение затруднения | 1100 | 550 |
| Генерация аналогичного задания | 850 | 350 |
| Проверка решения | 1000 | 250 |
| **Итого за цикл** | **3850** | **1400** |

Итого один цикл потребляет **5250 токенов**, из которых 3850 — входные и 1400 — выходные. В оценку входят повторно переданные инструкции и контекст; дополнительные запросы при ошибках сети, переспросах и проверках здесь не учитываются. Реальный объём зависит от промптов, длины истории диалога, токенизатора и внутренних особенностей API.

Для облачной модели стоимость рассчитывается по формуле:

`Стоимость = (входные токены × тариф входа + выходные токены × тариф выхода) / единица тарификации`.

### Предварительный расчёт для GPT-5 mini

`3850 × $0.25 / 1 000 000 + 1400 × $2.00 / 1 000 000 = $0.0037625` (около **0,30 ₽**) за цикл.

При **100 студентах**, каждый из которых проходит **20 таких циклов**, получится 2000 циклов и ориентировочно **$7.525** (около **606,19 ₽**) только за текстовые вызовы модели. Здесь не учитываются внешние инструменты, сервер приложения и возможные дополнительные запросы [1].

### Предварительный расчёт для YandexGPT Pro 5.1

`3850 × 0.40 ₽ / 1000 + 1400 × 0.40 ₽ / 1000 = 2.10 ₽` за цикл.

Для тех же 2000 циклов получится **4200 ₽**. Этот расчёт использует опубликованный тариф для Pro 5.1 и условно одинаковое число токенов; он **не является точным прогнозом счёта**, поскольку токенизация и применимый тариф могут различаться [2, 3].

### Цена усложнения архитектуры

Для ориентира можно рассмотреть упрощённый вариант, когда одна модель за один запрос получает 1600 входных токенов и возвращает 650 выходных. При тарифах GPT-5 mini расчёт составит **$0.0017** (около **0,14 ₽**) за такой запрос. Это приблизительно в **2,21 раза меньше**, чем четыре последовательных обращения из рассматриваемого учебного цикла. Но варианты пока нельзя признать эквивалентными по качеству: одиночный запрос может хуже различать причины ошибок или не выполнять все функции многоагентной цепочки. Проверка этого предположения относится к экспериментам.

## 4. Локальное развёртывание и ограничения ресурсов

Для Qwen3-8B исходные веса модели занимают около **16,4 ГБ** в репозитории Hugging Face [5]. Это не означает, что достаточно видеокарты с ровно таким объёмом памяти: при запуске дополнительно размещаются служебные данные и кэш внимания, размер которого растёт с контекстом и числом одновременных запросов.

В опубликованных разработчиками измерениях для Qwen3-8B при использовании Transformers потребление видеопамяти составляло примерно **15,9 ГБ для BF16** и **6,2 ГБ для AWQ-INT4** на минимальном входе; при контексте 6144 токена — примерно **16,8 ГБ** и **7,1 ГБ** соответственно [6]. Это результаты конкретной конфигурации, а не универсальные минимальные требования. Квантование сокращает потребление памяти, но его влияние на математическую точность нужно проверить отдельно.

Для учебного прототипа возможны три конфигурации:

1. **GPU с достаточной видеопамятью.** Предпочтителен для коротких задержек и последовательных запросов нескольких агентов; характеристики необходимо сопоставить с доступным оборудованием.
2. **Квантованная модель на менее мощном GPU.** Снижает требования к памяти ценой возможного изменения качества и производительности.
3. **Запуск преимущественно на CPU.** Позволяет экспериментировать без подходящей видеокарты, но ожидается более высокая задержка; её следует измерить, а не задавать произвольным числом.

При локальном размещении нужно учитывать защиту учебных данных, разграничение доступа, резервное копирование и журналирование. Отсутствие внешнего API не гарантирует безопасность само по себе. Для сопоставления облачной и локальной модели необходимо оценивать не только цену токенов, но также энергопотребление, стоимость оборудования, время настройки и число одновременно обслуживаемых студентов.

## 5. Лимиты запросов и деградация системы

В многоагентной системе рост расходов связан с повторными вызовами: одна ошибка в ответе может вызвать диагностику, уточнение, новое объяснение и проверку. Чтобы расходы не росли бесконтрольно, предлагаются следующие меры:

- **Учёт токенов по каждому агенту и учебной сессии.** Сохраняются название модели, входные и выходные токены, назначение запроса и его результат; персональные данные по возможности исключаются из технического журнала.
- **Ограничение длины контекста.** Вместо полной истории диалога агент получает краткое состояние обучения и относящиеся к задаче сообщения.
- **Ограничение числа повторов.** При неудачной генерации система не повторяет вызов бесконечно, а предлагает уточнить условие или использует заранее подготовленное задание.
- **Переключение режима работы.** При достижении порога бюджета необязательная генерация новых упражнений отключается; студенту остаются ранее подготовленные материалы и задания с детерминированной проверкой, если она применима.
- **Отказ без ложного подтверждения.** Если недоступна надёжная проверка математического ответа, система не должна автоматически сообщать студенту, что решение верное; вместо этого она явно указывает ограничение и предлагает альтернативный способ проверки.

Предполагается устанавливать два порога: предупредительный при достижении 80% выделенного лимита и критический при 100%, после которого платные генерации блокируются до пересмотра бюджета. Эти пороги являются проектным предложением, а не ограничением поставщика API. Переключение между провайдерами требует отдельно проверить совместимость форматов ответов, инструкций и авторизации. Для резервного подключения необходимо учитывать доступность провайдера в условиях эксплуатации.

## 6. Выводы для дальнейшей реализации

Для первого прототипа целесообразно предусмотреть единый интерфейс вызова модели, чтобы диагностика, объяснение и проверка не зависели от синтаксиса одного провайдера. Тогда кандидатов можно сравнивать на одинаковом наборе математических случаев, меняя модель и фиксируя качество объяснения, долю обнаруженных ошибок, потребление токенов и время ответа.

Предварительный расчёт показывает, что увеличение числа агентных вызовов повышает стоимость учебного цикла даже при использовании относительно недорогой модели. В то же время локальное размещение переносит расходы из тарификации запросов в инфраструктуру и сопровождение. Для практической реализации наряду с GPT-5 mini стоит рассматривать российский облачный сервис и локальное развёртывание. До окончательного выбора следует провести испытания на задачах по математическому анализу и линейной алгебре: проверять не только правильность итогового ответа, но и способность модели выявить конкретное затруднение и предложить полезный следующий шаг.
