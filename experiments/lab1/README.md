# Воспроизведение экспериментов

## Окружение
Python 3.12, SymPy 1.14.0 (mpmath 1.3.0). Для вызовов API используются только средства стандартной библиотеки. Локальный сервер Ollama: http://localhost:11434, установленная qwen3:8b Q4_K_M. Digest и версия сервера записаны в manifest.json. Модели код не скачивает.

Из корня проекта в PowerShell:
```powershell
python -m venv .venv
.\.venv\Scripts\python -m pip install -r requirements-experiments.txt
.\.venv\Scripts\python experiments/lab1/analyze.py
```
Существующее окружение повторно создавать не требуется. Анализ не обращается к API. Для чтения ноутбука достаточно просмотра GitHub; для интерактивного выполнения нужен установленный Jupyter либо VS Code с Python kernel, использующий окружение с SymPy. Jupyter в зависимости эксперимента не включён.

## Запуски
```powershell
# Полный новый эксперимент, 72 обращения:
.\.venv\Scripts\python experiments/lab1/runner.py --cases D1 D2 D3 L1 L2 L3 M1 M2 M3 --repeat 2
# Только второй повтор (seed 43) выбранных случаев:
.\.venv\Scripts\python experiments/lab1/runner.py --cases L1 M1 --repeat 1 --start-repeat 1
```
start-repeat=0 соответствует seed 42, start-repeat=1 — seed 43. Повторный запуск создаёт новый каталог, старые результаты не перезаписывает. Автоматических повторов при ошибках нет. Адаптер проверяет установленную модель через /api/tags до генерации. think=false передаётся полем API; /no_think не добавляется.

selection.json содержит точный список трёх запусков v2, включённых в сданный анализ. Новые запуски автоматически в сравнение не добавляются. Для анализа полного повторного эксперимента укажите в selection.json его каталог; ручные оценки нового текста должны быть выполнены заново и записаны в evaluation.json. Анализ проверяет полноту 54 сочетаний и отсутствие дублей case/variant/seed. Архивные журналы нужны также для проверки исходных SHA-256; не удаляйте их.

## Файлы и архитектура
- cases.json — 9 задач, решения студентов, памятки, эталоны. reference не передаётся модели.
- protocols/v2 — неизменные промпты и конфигурация итогового исследования, обоснования классификации, контрольные хеши архивов.
- runner.py — независимый от конкретного транспорта цикл; OllamaAdapter реализует metadata/prepare/generate. Для другого провайдера добавляется адаптер и запись в реестр; нормализованный ответ содержит text/model/metrics/raw.
- runner_v1.py, prompts.json, config.json — сохранённая реализация исходного пилота v1, исключённого из итоговой оценки.
- runs/*/manifest.json — модель/digest, версии, снимки данных и промптов, параметры. requests.jsonl сохраняет тело перед отправкой; responses.jsonl — полный ответ, ошибку и время. summary.json — автоматическая сводка. Старые ручные оценки сохранены как история этапов; итоговая оценка v2 находится в evaluation.json.
- analyze.py — проверка полноты, неизменности промптов/данных/параметров, метрик и архивов; пересчёт results/aggregate.json, evaluated.json, comparison.csv.

## Оценивание
conceptual — нарушение/пропуск правила; arithmetic — арифметическая или алгебраическая ошибка после правильного выбора метода; none — верное решение. D1/L1/M1 — conceptual, D2/L2/M2 — arithmetic, D3/L3/M3 — none.

internal содержит диагностику и может содержать правильный результат. Только student_message предназначено студенту. Номер шага и тип сравниваются автоматически. Математическая корректность текста 0/1, отсутствие готового ответа 0/1 и полезность 0–2 оцениваются вручную, с пояснением на каждый ответ. Формально верное напоминание правила может быть неуместным и получить 0 за полезность. Подтверждение правильного решения учитывается отдельно. SymPy проверяет доверенные эталонные выражения, а не выполняет код или выражения из ответов модели.

## Измерения и ограничения
prompt_eval_count/eval_count — реальные счётчики Ollama. wall_seconds — секунды клиента; поля Ollama *_duration — наносекунды. Для C учитываются оба вызова. Загрузка, прогрев и кэш влияют на время; порядок A/B/C фиксирован. Стоимость электричества, загрузка GPU и денежные затраты не измерены. Нет гарантии побитового повторения при изменении сервера/оборудования. Малый синтетический набор и два seed не обеспечивают статистическую значимость.
